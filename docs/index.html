Work with huge SVG files without losing a byte.

vexel is a native macOS workbench for very large SVG documents. It keeps your source exactly as written, indexes in small steps so the interface stays responsive, and treats every file as untrusted input. Written in C17 with no third-party libraries.

Built around six commitments

Most SVG tools parse a file into their own model and write a different one back. On large, hand-tuned or generated documents that costs time, metadata and clean diffs. vexel takes the opposite approach.

Source-preserving

Your bytes stay yours

The document is borrowed source plus spans. Unknown elements, namespaces and formatting are never rewritten, and a no-op save writes the exact original bytes through an atomic rename.

Responsive

Large files, small steps

Indexing runs in byte-budgeted steps on a job scheduler, so the main thread never waits on a big document. Rendering is tile-based, backed by a spatial index and tile cache.

Safe by construction

Every file is untrusted

Explicit limits on size, depth and work, checked arithmetic, no unbounded recursion. Scripts, external entities and external resources are never loaded. The tokenizer and shape decoder are fuzzed under ASan and UBSan.

Self-contained

C17, zero dependencies

CMake and Ninja, no package manager, no configure-time downloads. A Release svgworkbench binary is about 200 KB.

Native

Apple Silicon first

Metal presentation and a custom-drawn UI with real keyboard semantics. Platform code sits behind narrow interfaces instead of leaking through the codebase.

Verifiable

Checked, and written down

Output is compared with pinned librsvg renders under fixed pixel thresholds, used only as a test baseline. Architecture decisions and performance methodology are public in the repo.

How a document flows through vexel

Source bytes are never copied into a second model. Everything downstream holds offsets into them.

Honest status

vexel is not a usable editor yet. This is what exists today and what does not.

Rendering covers a bounded subset of SVG. In the current 58-file real-world corpus only 2 files preview fully; the rest are reported as unsupported rather than guessed at. Unsupported content is never silently dropped, and no comparative speed claims are made. Methodology is in docs/PERF.md.

Build it

Apple Silicon Mac, macOS 13 or later, Xcode Command Line Tools, CMake 3.25+ and Ninja. Apple Silicon macOS is the only supported platform for now.

git clone https://github.com/megasoft1978/vexel
cd vexel
./dev build
./build/mac-debug/bin/svgworkbench --version
./dev verify     # build + fast tests
./dev asan       # AddressSanitizer
./dev ubsan      # UBSan
./dev shape-fuzz --duration 60 --seed 1
