# Goal
Add a reproducible, black-box macOS benchmark harness that records comparable SVG render trials when adapters are available and reports unsupported work without fabricating results.

# Existing contracts and invariants
- Apple Silicon macOS 13+ only; no package installation, network, cross-platform support, or external source inspection.
- Inputs must match the pinned corpus manifest. Never load SVG-referenced external resources.
- Launch processes with argv arrays and `shell=False`; bound timeout, output capture, trial count, RSS sampling, and generated files. Write all temporary inputs/outputs under repo-local `.cache/`.
- Record missing executables and unsupported capabilities as unavailable with an explicit reason. Empty measurements are not zero measurements. This harness is measurement infrastructure, not a marketing comparison.
- Distinguish process-cold launch from warm-repeat runs. Do not claim filesystem cache eviction. Run at least five trials per measured condition and report raw observations plus median and p95.
- Never compare different task semantics or resolutions. Include exact executable version, argv, fixture hash, dimensions, OS, architecture, hardware, Python version, and limits in machine-readable output.
- Do not overwrite existing result files unless their schema/work-order identity matches; install JSON and CSV atomically.

# Required implementation
1. Add a standard-library-only benchmark CLI with `--smoke` and `--run` modes. `--smoke` validates the pinned corpus and records adapter availability without requiring competitors. `--run` measures the Vexel CLI version probe and render adapters available through a documented, strict JSON adapter configuration; include optional auto-discovery for `inkscape` and `donner` executables without installation.
2. Render the same three pinned fixtures (`shapes-basic`, `stress-many-shapes`, `stress-long-path`) at 256x256 for each adapter that declares a compatible render command. Require five process-cold trials and five warm-repeat trials per fixture, with a bounded timeout. Configured commands are argv arrays using only `{input}`, `{output}`, `{width}`, and `{height}` substitutions; reject shell strings, unknown placeholders, and unsafe output paths.
3. Capture each trial's exit code, elapsed monotonic time, sampled peak RSS where observable, output PNG size/hash, and bounded stdout/stderr previews plus hashes. A nonzero exit, timeout, missing output, or malformed PNG is a failed trial, never silently excluded. Report median and nearest-rank p95 for latency/RSS only when enough valid trials exist.
4. Record exact software/hardware/OS metadata, corpus/source hashes, adapter identity/version/path, task/argv, warm/cold condition, trial count, limitations, and unavailable reasons. Emit stable JSON and CSV raw trial artifacts atomically. Do not claim performance advantage from unavailable or unlike tasks.
5. Add an offline fake-process adapter for tests that emits a deterministic 256x256 PNG, plus injected timeout, nonzero-exit, missing-output, malformed-output, shell-injection, unsafe-path, and report-tamper tests. Tests must not require competitor applications or network.
6. Add a concise `bench/harness/README.md` and update `docs/PERF.md` with the protocol and the current smoke result, clearly marking missing competitor/render measurements as unavailable.
