# Goal
Run bounded XML-tokenizer fuzzing on macOS CI and preserve minimized, reproducible crash evidence linked to stable issue IDs.

# Context pointers
- Read: `AGENTS.md`, `OWNER-DIRECTIVES.md`, `STATE.md`, `docs/CODING_STANDARD.md`, `docs/research-r4/05-revised-roadmap.md`, `docs/research-r4/06-risks-and-safety.md`, `docs/research-r4/04-llm-aware-design-changes.md`, `docs/adr/0002-source-preservation-and-provenance.md`, `src/svg/xml/README.md`, `tests/fuzz/README.md`, `scripts/check_fuzz_workflow.py`, `.github/workflows/fuzz.yml`.
- The existing fuzz workflow is macOS-only, read-only, action-SHA-pinned, with a 3-second PR run and a 60-second schedule. Extend it to a 30-second PR smoke and a 600-second scheduled campaign.
- Frozen tests/oracles: `tests/oracle/**`, `tests/golden/**`, `bench/corpus/**` and their manifests are read-only. Do not edit `tests/test_boot05.py` or weaken existing fuzz/CI policy checks.
- No network fetch, dependency, or other-OS workflow/runner.

# Existing contracts and invariants
- Apple Silicon macOS 13+ only; C17; source input remains bounded to M2-02's 16 MiB cap and 256 depth cap.
- Fuzz execution uses a fixed, recorded seed; input generation and tokenizer calls have bounded memory, wall time, and work per case.
- The fuzz process performs no network, file, or resource loading. Only the campaign controller may write below `.cache/WO-M2-03/` and `artifacts/WO-M2-03/`.
- Keep full sanitizer diagnostics. A minimized failure must reproduce under the same seed/input and retain the original input hash, signal/status, normalized stack fingerprint, build identity, and reproduction command.
- Every retained regression record has a unique stable local issue ID and points to its seed, input hash, fingerprint, and replay test. Never fabricate a parser crash; a synthetic harness canary must be clearly labeled as such.

# Required implementation
1. Add `./dev fuzz-xml` with an explicit seed and duration. It builds the macOS ASan/UBSan tokenizer target, runs the campaign controller, enforces a 30-second PR smoke and 600-second maximum campaign duration, and writes only task-local cache/artifacts.
2. Extend the native fuzzer to expose deterministic replay of a seed/iteration and one-input mode. On a failure, retain enough bounded progress/input data to recover the exact crashing input; do not emit or store every successful input.
3. Add a campaign controller that supervises the fuzzer in its own process group, kills the whole group on timeout, records toolchain/build/seed/duration/iteration counts, and returns nonzero on crash, sanitizer output, invariant failure, or timeout.
4. On failure, preserve the raw sanitizer output and a normalized stack fingerprint (stable frame text with addresses and volatile temporary paths removed). Recover the failing input by deterministic replay, run a bounded delta minimizer that never increases input size, and confirm the minimized input reproduces the same fingerprint. Preserve the original input and minimized result under `artifacts/WO-M2-03/failures/`; report SHA-256, seed and iteration, signal/status, reproduction command, and fingerprint.
5. Store retained regressions in `tests/svg/xml/fuzz/regressions.json`; every entry uses a unique `XML-FUZZ-NNNN` issue ID, names the seed file and input hash, and is replayed by a deterministic regression test. Do not add an actual regression entry unless a real minimized failure is reproduced. Add a separately labeled synthetic crash canary for testing the capture/fingerprint/minimize path.
6. Add tests for the known canary seed, crash fingerprint stability, minimizer size/reproduction, timeout process-group cleanup, input/resource bounds, report path confinement, and issue-ID-to-seed replay mapping.
7. Update `.github/workflows/fuzz.yml`: macOS `macos-15` only; PR/manual run for 30 seconds; weekday schedule for 600 seconds; job timeout no more than 20 minutes; `contents: read`; no secrets; every action pinned to a full commit SHA. Retain failure JSON/input/stack files in the job log or a narrowly scoped failure artifact. Do not add Linux/Windows runners or CI matrices.
8. Update `scripts/check_fuzz_workflow.py` and add policy tests for both durations, runner/permissions, timeout, pinned actions, absence of secrets, and failure-artifact path confinement. Preserve the existing BOOT-05 checks.
9. Keep source files below 500 lines where practical and below the 800-line hard limit. No third-party fuzzer, serializer, parser feature, external resource access, or performance claim.
