# Goal
Render the corpus-relevant SVG presentation-style subset with deterministic cascade and inherited paint state while preserving the original source bytes.

# Context pointers
- Read: `AGENTS.md`, `OWNER-DIRECTIVES.md`, `STATE.md`, `docs/CODING_STANDARD.md`, `docs/research-r4/05-revised-roadmap.md`, `src/svg/shape/README.md`, `src/svg/shape/shape.c`, `src/svg/shape/shape.h`, `tests/svg/shape/test_shape.c`, `tests/test_shape_render.py`, and `reports/M4/corpus-feature-frequency.md` / `.json`.
- CSS/SVG semantics: W3C SVG 2 Styling, https://www.w3.org/TR/SVG2/styling.html and CSS Cascade Level 3, https://www.w3.org/TR/css-cascade-3/ (consulted 2026-10-09). Use as specification references only; do not read renderer/editor source.
- The external real corpus is read-only. Existing M4 inventory reports `.land`/`.series` rules and class-based paint in generated examples. Do not copy corpus files into this repository.

# Existing contracts and invariants
- C17, Apple Silicon macOS 13+ only; no portability code, dependency, or network access.
- Shape decoder borrows and preserves exact source bytes; decoded arrays are owned by the document and released by its destroy function.
- Existing basic-shape geometry, fill/stroke raster semantics, transform stack, byte offsets, and unstroked output remain stable unless a newly styled paint value changes the expected image.
- Direct presentation attributes are currently supported on shapes. This WO adds style resolution for root `svg`, groups, and the currently supported basic shape elements; it does not add geometry elements.
- Supported paint properties are exactly: `fill`, `fill-rule`, `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-miterlimit`, `stroke-dasharray`, and `stroke-dashoffset`. Preserve source bytes for every supported or unsupported declaration.

# Required implementation
1. Add a focused CSS subset module with a public contract and module README. Use source spans or bounded slices; no source rewriting. Bound stylesheet bytes, rules, selectors, declarations, class tokens, and all allocation arithmetic. Free all temporary state on every error path.
2. Parse internal `<style>` content and `style` attributes for simple compound selectors consisting of an optional supported element name, at most one `#id`, and zero or more `.class` terms; comma-separated selector lists are allowed. Match class tokens separated by CSS whitespace. No combinators, pseudo-classes, attribute selectors, namespaces in selectors, imports, URLs, or external resources. Ignore unsupported selectors and at-rules without executing or fetching anything.
3. Recognize the nine paint properties listed above. Ignore unsupported declarations and unsupported values while leaving the source slice untouched. Parse comments, whitespace, declaration boundaries, duplicate declarations, and `!important` sufficiently to apply the stated subset's cascade. Malformed declarations must not corrupt neighboring declarations; invalid values for a recognized paint property produce a stable unsupported/number diagnostic at the value offset rather than silently substituting a default.
4. Resolve presentation attributes, matched stylesheet declarations, and inline style with CSS precedence: presentation attributes have specificity zero; stylesheet rules use ID/class/type specificity then source order; inline declarations outrank normal stylesheet declarations; `!important` outranks normal declarations and is resolved by importance, specificity, then source order. Same-priority duplicate declarations use the last declaration. Initial values and inheritance for the nine listed properties follow SVG defaults; computed inherited state flows through `svg` and nested `g` into shapes. Geometry attributes and transforms retain their current precedence and behavior.
5. Add tests for cascade order, specificity, comma lists, class token matching, inheritance through nested groups, initial defaults, inline and `!important`, duplicate/invalid/unsupported declarations, comments/whitespace, stylesheet limits, source byte equality, exact diagnostic offsets, and deterministic output. Add `rsvg-convert` differential fixtures for the supported CSS cases; keep existing jointly-covered pixel thresholds unchanged.
6. Run the real corpus harness and preserve all 58 input hashes/outcomes. Record how many files gain previews and per-tier comparisons in existing M3 report formats; state clearly this remains open/index evidence, not full-render parity. Do not claim unsupported features are rendered.
7. Add a fixed CSS-heavy renderer benchmark (stylesheet/class and inline-style workloads) with raw trials, median/p95, throughput, output hash, and process RSS. Compare to the frozen pre-WO source where the workload has a meaningful prior equivalent; otherwise report no baseline.
