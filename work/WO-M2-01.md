# Goal
Add a bounded C17 byte-slice, checked-size arithmetic, and arena API with boundary and allocation-failure coverage.

# Context pointers

- Relevant decisions: C17, Apple Silicon macOS 13+, MPL-2.0, minimal dependencies, explicit ownership, bounded allocation.
- No external source, network access, third-party code, or corpus changes.

# Existing contracts and invariants
- Exported symbols use the `base_` prefix. Public APIs return explicit status or boolean values and use pointer-plus-length slices.
- A slice is valid when its pointer is non-null or its length is zero. Sub-slices require checked bounds and preserve the empty-slice representation.
- Checked add/multiply fail without wrapping and initialize valid output pointers to zero on failure.
- Arena memory is single-owner and not thread-safe. Pushed pointers remain valid until reset or destroy. Reset retains chunks for reuse.
- Arena capacity limits the sum of chunk payload capacities, excluding chunk headers. All growth and alignment arithmetic is checked before allocation.
- Alignment must be a power of two from 1 through 4096. An empty push returns success with a null output pointer and consumes no capacity.
- Allocator callbacks are either both supplied or both omitted. The arena owns every allocation made through its allocator and frees all chunks at destroy.

# Required implementation
1. Add checked `size_t` addition and multiplication with defined null-output, overflow, and failure behavior.
2. Add immutable and mutable byte slices with validity checks, checked sub-slicing, and byte equality. Do not infer lengths from NUL termination.
3. Add a bounded chunked arena with configurable initial chunk size, total payload-capacity limit, optional paired allocator callbacks, aligned pushes, reset, statistics needed for tests, and destroy.
4. Reject invalid alignment, malformed allocator configuration, arithmetic overflow, and capacity exhaustion without partially changing arena state. Preserve arena state when an injected allocation fails.
5. Add a C test executable under CTest. Include fixed-seed boundary/property checks for arithmetic and slices; alignment and bounds checks; reset/reuse checks; limit and allocation-failure injection; and exact cleanup counts.
6. Make `./dev verify` run Debug CTest in addition to the Python fast suite. Apply the existing strict warning profile to the base library and C tests; ASan/UBSan profiles must instrument the library and test executable.
7. Add `src/base/README.md` documenting API contracts, ownership/lifetime, limits, error behavior, and thread-safety. Record binary size, arena boundary metrics, test/sanitizer evidence, and absence of SVG throughput/RSS claims in the benchmark result and `docs/PERF.md`.
