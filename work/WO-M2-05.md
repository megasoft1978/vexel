# Goal
Decode a documented, bounded SVG root/rect/path subset and rasterize supported filled geometry deterministically into a CPU RGBA tile.

# Existing contracts and invariants
- Apple Silicon macOS 13+ only. C17, strict existing warning profile, no other-OS source or stubs.
- XML tokens and attribute values borrow the original bounded source. Preserve the original document bytes; this work adds no serializer or source mutation.
- Use `raster_tile` ownership and dimensions contracts. All allocations, dimensions, coordinates, path commands, flattened segments, and raster work must be explicitly bounded with checked arithmetic.
- Supported path syntax: absolute and relative M/m, L/l, H/h, V/v, C/c, Q/q, A/a, Z/z; repeated operand groups; subsequent coordinate pairs after M/m are line segments. Arc flags are exactly 0 or 1. Reject smooth commands, malformed separators, missing operands, invalid flags, non-finite values, unsupported units, and unsupported element/attribute semantics with stable diagnostics and byte offsets.
- Root viewport accepts unitless or px width/height and a finite positive viewBox. Raster dimensions are 1..4096 per axis and at most 16,777,216 pixels. Coordinates are bounded to absolute value 1,000,000 before transforms (no transforms in this subset). Path commands and total decoded segments are each capped at 65,536; flattened output is capped at 262,144 edges/document.
- Rect supports x, y, width, height, with omitted x/y defaulting to zero. Negative dimensions reject; zero dimensions are safely empty. Fill supports `none`, `#RGB`, `#RRGGBB`, and named `black`, `white`, `red`, `green`, `blue`; omitted fill defaults to black. Fill rule supports `nonzero` and `evenodd`. CSS, style, stroke, transforms, gradients, filters, text, external resources, and unknown geometry are unsupported; report them and retain source.
- The scalar rasterizer uses pixel-center sampling, deterministic curve/arc flattening with bounded subdivision and a documented flatness rule, and a documented fill rule implementation. Output is transparent black where no supported fill covers a pixel. No SIMD, GPU, or performance claim is required.

# Required implementation
1. Add focused geometry and SVG-shape modules with README documentation of supported grammar, diagnostics/source offsets, ownership, limits, fill semantics, and deterministic raster behavior.
2. Decode tokenized SVG root, rect, and path elements without rewriting source. Unsupported syntax must produce a stable diagnostic category and source byte offset; source remains available unchanged.
3. Parse supported numeric syntax without locale dependence; reject overflow, NaN/infinity, invalid flags, missing parameters, and over-limit values before unsafe arithmetic or allocation. Use checked size operations and no VLAs.
4. Flatten cubic/quadratic curves and elliptical arcs deterministically, respecting stated output and subdivision caps. A cap exhaustion is a bounded diagnostic, never unbounded work or partial unsafe output.
5. Rasterize supported closed/open fill geometry into transparent RGBA CPU tiles with deterministic pixel-center coverage and nonzero/evenodd fill behavior. Define how open subpaths close for fill, consistent with SVG.
6. Add project-authored simple rectangle, line, cubic, quadratic, arc, fill-rule, and degenerate fixtures. Compare the supported cases with `rsvg-convert` output using a documented edge-pixel tolerance for renderer antialiasing; independently require deterministic byte-identical output across repeated Vexel runs. Do not modify frozen oracle/golden files.
7. Add a fixed-seed sanitizer fuzz campaign for malformed and boundary SVG inputs, with a configurable fixed duration/case count, bounded input size, deterministic seed reporting, and no network/resource loading. Include adversarial huge/non-finite coordinates, degenerates, malformed command streams, and cap exhaustion.
8. Integrate focused shape tests into CTest and `./dev verify`; keep added files under 500 lines where practical and 800 lines hard. Build Debug, Release, ASan+UBSan, and UBSan under the existing macOS-only presets.
9. Record renderer executable/version, corpus fixture hashes, test/fuzz counts and duration, Release binary/library sizes, and any measured throughput/RSS with method in the JSON result and `docs/PERF.md`. If throughput/RSS is not measured, state that plainly.
