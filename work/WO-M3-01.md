# Goal
Index large borrowed SVG byte slices incrementally, emit a renderable first supported shape and loading progress before the full index completes, and cancel stale generations safely.

# Context pointers
- Read: `AGENTS.md`, `OWNER-DIRECTIVES.md`, `STATE.md`, `docs/CODING_STANDARD.md`, `docs/research-r4/05-revised-roadmap.md`, `docs/research-r3/plan/02-architecture.md`, `docs/research-r3/plan/06-benchmark-and-quality.md`, `docs/adr/0004-macos-only-platform.md`, `docs/adr/0006-m1-04-task-queue.md`, `src/base/README.md`, `src/base/base.h`, `src/platform/platform_task.h`, `src/svg/xml/README.md`, `src/svg/xml/xml_tokenizer.h`, `src/svg/shape/README.md`, `src/svg/shape/shape.h`, and `src/raster/README.md`.
- Preserve the one-shot XML tokenizer defaults and all M2 source-span/diagnostic behavior. The new incremental reader may expose a separate 1 GiB source limit; never raise the existing one-shot default.
- Benchmark hardware is the named current host: Mac Studio (Mac17,14), Apple M5 Max, 64 GiB RAM, macOS 27.0, Apple Clang 21.0.0. Record actual toolchain and machine metadata in every result.
- No network, external dependencies/algorithms, or third-party source. Do not touch frozen oracle/golden manifests or prior results.

# Existing contracts and invariants
- C17, Apple Silicon macOS 13+ only, pointer+length slices, checked arithmetic, no VLAs, explicit ownership, no unsafe string functions.
- Source bytes are immutable and borrowed for the session lifetime. All emitted spans are absolute byte offsets into that exact source.
- The XML reader must preserve M2 tokenizer error categories, offsets, depth/attribute/node limits, quote/comment/CDATA states, and unsupported-DTD behavior. It must not resolve entities or load resources.
- Index limits: source <=1 GiB, nesting <=256, elements <=1,000,000, attributes <=1,000,000, element-index bytes <=256 MiB, at most 64 KiB source advancement per `svg_index_step`, and bounded checked allocations. Oversize input fails before reading or allocating proportional to its length.
- The first preview covers only the existing supported root/rect/path shape subset. Unsupported elements remain source-backed index entries with an explicit unsupported status; they are never silently interpreted or removed.
- Progress/callback data and preview results are generation-tagged. Cancellation is cooperative and bounded between work steps; the existing task queue owns worker joins, and stale generations cannot publish a tile.
- Mutable index state is owner-thread-only. A preview tile/result transfers ownership explicitly; callbacks never retain borrowed token scratch.

# Required implementation
1. Add a resumable XML reader that advances over the immutable complete source with a caller-supplied byte budget. Preserve absolute source spans, nesting state, error offsets, and one-shot token equivalence for existing <=16 MiB fixtures. Keep `svg_xml_tokenize` behavior/defaults unchanged.
2. Add `src/svg/index` session APIs for start, step, progress query, generation advance, cancellation, preview take, completion, and destruction. Each call checks the 1 GiB, 256-depth, 1,000,000-element/attribute, 256 MiB index-storage, and 64 KiB-step limits before allocation or work.
3. Store stable source-backed element records (depth, parent/range, source span, supported/unsupported status) without building a DOM or copying source text. Preserve unknown elements and unsupported feature status.
4. Once the first complete depth-1 supported `rect` or `path` is available, schedule its bounded shape decode/raster on the existing task queue and publish the owned preview tile before complete-document indexing. Do not block the UI/owner step on that render. Reject malformed source with a stable diagnostic; a preview may be visible before a later malformed tail is discovered, but the session must then report failure and never claim the document complete.
5. Expose monotonic byte/node progress at 10%, 50%, 90%, and completion. Cancel at any step; advancing the generation invalidates pending previews/results. No canceled or stale result can be presented. Ensure queue/task context and source lifetimes remain valid through completion/join.
6. Add a small loading/progress UI state path and scripted driver assertions for progress, first-preview-ready, cancel, and stale-generation events. No general navigation/editor controls are in scope.
7. Add deterministic synthetic generators for a 10 MiB / 100,000-simple-element input and a 100 MiB map-like input. Measure source-read time separately from first-preview latency and complete-index time. Run five first-use trials and ten warm trials; record raw trials, median, p95, max per-step latency, peak RSS, bytes/index, machine/compiler/build, generator seed, and cache caveats.
8. On the named Mac, first preview from index start must have median <1.0 s for the 10 MiB case and <2.0 s for the 100 MiB case. No owner/UI step may exceed 100 ms in scripted progress/cancel runs. Peak RSS for the 100 MiB simple/map-like case must be <=3x source size plus 128 MiB fixed process allowance; report all measured values even on failure.
9. Inputs larger than 1 GiB must return the explicit source-limit result before dereferencing source bytes or allocating source-proportional storage. Test using a non-dereferenced oversized slice; do not create a 1 GiB checked-in or retained artifact.
10. Keep new C/Python source files under 500 lines where practical and below 800 lines hard. Add module READMEs and API ownership/threading/limits docs.
