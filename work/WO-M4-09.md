# Goal
Record, for every pinned real-corpus file, whether a **full-document render** succeeds and, when it fails, the specific error category and source offset. Today the only corpus report measures a synthetic single-element preview built by `svg_index_make_preview_source`, so no per-file render diagnostic exists and no blocker can be prioritised by real impact.

- The external corpus lives outside the repository at `/Users/megasoft78/Desktop/Freelance/vexel-corpus-real` and is read-only. Its `manifest.json` SHA-256 is `9fbf9a2f384d70a41da72e99ac259d2c5d137ffd3c8a01ce4be4741c1c29bc30` and lists 58 files. No corpus file may be copied into the repository.
- The render CLI is `build/mac-release/bin/svgworkbench --render-frame FILE --size WxH --out FILE.ppm`. On failure it writes `render-frame: <path>: <category> at byte <offset>` to stderr and exits non-zero. Categories come from `svg_shape_error_name` in `src/svg/shape/shape.h` and `src/svg/shape/document.c`.
- `reports/M4/head-to-head.md` is the existing (preview-based) report; it is not to be rewritten by this order.

# Existing contracts and invariants
- Corpus files are borrowed, read-only inputs; never modify, move, rename, or copy them into the repository.
- The report must be reproducible from the pinned manifest hash; if the manifest hash differs, the tool must fail loudly rather than silently reporting on different inputs.
- No network access and no new dependency. Python 3 standard library only.
- Unsupported/limit outcomes are data, not errors: the tool succeeds when it has recorded every file's outcome.
- Do not weaken, change, or delete any existing test, golden, or oracle.

# Required implementation
1. Add `scripts/corpus_render_report.py`. It must:
   - accept `--corpus PATH` (default `/Users/megasoft78/Desktop/Freelance/vexel-corpus-real`), `--binary PATH` (default `build/mac-release/bin/svgworkbench`), `--size WxH`, `--max-bytes N`, `--timeout SECONDS`, `--output-json PATH`, `--output-markdown PATH`, and `--trial-timeout-grace`;
   - read the corpus `manifest.json`, recompute its SHA-256, and abort with a non-zero exit and a clear message unless it equals the pinned digest recorded in this order;
   - run one full-document render trial per manifest file whose size is at or below `--max-bytes`, recording for each file: relative path, byte size, `verdict` (`ok`, `unsupported`, `limit`, `xml`, `number`, `viewport`, `path`, `oom`, `timeout`, `error`), the raw diagnostic category string, the diagnostic byte offset when present, the exit code, a `timed_out` boolean, and a short bounded source excerpt around the offset. Wall-clock timing is deliberately excluded from the JSON so that the JSON is byte-reproducible; the Markdown summary may report elapsed milliseconds because it is not a machine input;
   - record files above `--max-bytes` as `skipped` with the reason, so the report always accounts for all 58 entries;
   - write deterministic, key-sorted JSON and a Markdown summary containing a category histogram, the per-file table, and the list of files that render;
   - never write outside `reports/M4/` unless an explicit output path is given, and never modify the corpus.
2. Add `tests/test_corpus_render_report.py` covering, without the real corpus or the real binary:
   - manifest digest mismatch aborts;
   - each diagnostic string shape maps to the expected verdict, including a missing/invalid offset and an unrecognised category;
   - size filtering and the `skipped` accounting keep the total equal to the manifest entry count;
   - a fake binary adapter that emits a known stderr string produces the expected record;
   - JSON output is deterministic across two runs on the same inputs.
3. Generate `reports/M4/render-diagnostics.md` and `.json` from the real corpus at the pinned digest and record the observed counts.
4. Document the tool, its inputs, and its limits in `docs/testing.md`.
