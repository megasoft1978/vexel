# Goal
Add an explicit initializer for a valid empty native timeline-v1 payload, using caller-supplied timing and display settings. Keep zero-length timeline bytes distinct from unsupported nonempty bytes, so the app can initialize lazily inside the first successful authoring transaction and undo back to the original empty payload.

# Context and contract
- Read `OWNER-DIRECTIVES.md`, `docs/adr/0020-native-animation-schema-v1.md`, `rust/crates/vexel-timeline/src/schema.rs`, `rust/crates/vexel-timeline/src/edit.rs`, and current timeline tests.
- ADR-0020 fixes schema/version and validation: timebase 1..240 ticks/sec, duration 1..14,400,000 ticks, exact rational frame-rate representation, loop mode, onion bounds, and empty ordered tracks.
- Caller supplies timing and display values; do not invent project defaults. Validate the generated bytes through the existing decoder and context before returning them.
- The ordinary `TimelineEdit::new` behavior for arbitrary nonempty input remains strict. Never reinterpret `{}` or any unsupported nonempty payload as an empty v1 timeline.
- Avoid new dependencies or manifest/lock changes. Write focused tests but do not execute tests/builds; final verification is deferred until all implementation slices are complete.

# Allowed paths
- New `rust/crates/vexel-timeline/src/edit/initialize.rs`
- New focused `rust/crates/vexel-timeline/src/edit/initialize_tests.rs` or the crate's existing test location, if needed
- `rust/crates/vexel-timeline/src/edit.rs` only for module registration/re-export of the new initializer API
- `rust/crates/vexel-timeline/src/lib.rs` only if a public re-export is needed
- `work/WO-RUST-V1-EMPTY-TIMELINE-01.md`, its artifact directory, and `ledger.jsonl` are coordinator-only.

# Protected paths
All other timeline source, app/session/history/recovery files, manifests/locks, ADRs, fixtures/oracles/goldens, C/Python migration references, `OWNER-DIRECTIVES.md`, and external directories. No dependencies, broad schema redesign, test weakening, or verification execution.

# Acceptance criteria
- AC-1: An explicit settings type/API constructs the complete required `vexel.animation` version 1 object with zero tracks and caller-supplied settings.
- AC-2: The constructed payload is validated using `decode` and the supplied `TimelineContext` before it is returned.
- AC-3: Invalid timing, unrepresentable frame rate, duration, loop/onion values, allocation failure, or validation failure returns a typed error without exposing partial output.
- AC-4: Zero-length source remains the legacy empty timeline; `{}` and unknown/non-v1 nonempty inputs are not accepted as initialized v1 data or rewritten.
- AC-5: No new dependency; source files remain under 800 lines; focused tests are authored and left unrun.
