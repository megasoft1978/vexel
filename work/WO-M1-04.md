# Goal
Add a bounded macOS task queue with generation-aware cancellation and shutdown that joins all workers.

# Existing contracts and invariants
- macOS 13+ Apple Silicon only. C API in `src/platform/`; pthread implementation under `src/platform/macos/`; no non-macOS stubs.
- Queue capacity is finite (1–64); worker count is finite (1–4). Reject invalid configuration and queue-full submission.
- The queue never owns job context. Callers keep it alive through completion/cancellation. Results are copied scalar values with task ID and generation.
- Cancellation is cooperative. Callbacks poll the provided atomic cancellation flag and return promptly. Shutdown requests cancellation, wakes workers, joins them, then releases storage.
- The queue owner must quiesce all callers before destroy: no concurrent entry may begin and no API call may be in flight. Destroy with concurrent entry is undefined behavior. A debug/assert-enabled active-call counter must deterministically abort if destroy begins while an admitted call remains active; a test hook pauses a caller inside the API and a death-test subprocess verifies the assertion.
- Generation advances are monotonic. Old queued work is discarded, old running work is canceled, and old completions cannot be returned as publishable results.
- No locks are held while callbacks run. Never call client callbacks while holding the queue mutex.

# Required implementation
1. Define an opaque C task-queue interface with bounded configuration, submit, per-task cancel, advance-generation, poll-completion, and shutdown operations.
2. Implement queued and running cancellation, cooperative atomic cancellation tokens, and generation checks at completion publication. Queue-full, duplicate/stale IDs, and callback failure must return bounded errors without leaking resources. Cancellation and joining worker tasks must be race-free and bounded. Concurrent API entry during destroy is outside the contract; the owner-quiescence rule and deterministic debug assertion above cover misuse.
3. Make queue and fixed-capacity slot storage allocation injectable through configuration for deterministic allocation-failure testing. Every partial initialization failure must release earlier allocations and join any workers already started.
4. Add native task checks that verify queued cancellation, running cancellation, stale-generation suppression, callback-result publication for the current generation, and clean shutdown. Run 1,000 create/submit/cancel/join cycles; each shutdown must finish within 2 seconds. Add a deterministic death test: pause an API caller after admission, invoke destroy in the same process, and require the debug assertion to abort in a subprocess.
5. Fix the M1-03 test-harness follow-up: the focused replay integration test must run the current Debug executable when invoked by `./dev verify` after its Debug build, even if an old Release executable exists. The frozen M1-03 CLI acceptance still exercises Release after the verifier prebuild.
6. Document queue limits, caller context lifetime, cancellation cooperation, stale-result behavior, shutdown order, and the limit that an uncooperative callback can delay join.
