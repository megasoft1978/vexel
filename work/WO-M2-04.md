# Goal
Implement a bounded macOS atomic no-op save that preserves the exact original XML bytes and leaves the destination unchanged on parse or pre-commit I/O failure.

# Context pointers
- Read: `AGENTS.md`, `OWNER-DIRECTIVES.md`, `STATE.md`, `docs/CODING_STANDARD.md`, `docs/adr/0002-source-preservation-and-provenance.md`, `src/base/README.md`, `src/base/base.h`, `src/svg/xml/README.md`, `src/svg/xml/xml_tokenizer.h`, `src/platform/README.md`, `src/platform/macos/README.md`, and `docs/research-r4/05-revised-roadmap.md`.
- Existing source-preservation decision: original source bytes remain authoritative for no-op save; do not serialize tokens.
- Platform support: Apple Silicon macOS 13+ only. Keep filesystem-specific replacement behind a `platform/` interface; do not add other-OS implementations or stubs.
- Frozen paths: `tests/oracle/**`, `tests/golden/**`, `bench/corpus/**`, `work/**` other than this ready WO, and all prior benchmark results/artifacts are read-only.
- No network, dependencies, external algorithms, or SVG-editor source.

# Existing contracts and invariants
- C17, pointer+length byte slices, checked size arithmetic, no VLAs, bounded paths, explicit ownership, and no unsafe string functions.
- XML input is limited by the M2-02 tokenizer defaults (16 MiB input, 256 depth). Save bytes exactly as received; do not normalize UTF-8, line endings, whitespace, namespaces, comments, metadata, quotes, or unsupported elements.
- Parse/tokenization must complete successfully before any filesystem mutation. Failure must not create, truncate, or replace the destination.
- Destination replacement is atomic within its parent directory. Existing POSIX permission bits are retained. Temporary files are exclusive, same-directory, and removed on pre-commit failure.
- No-op save is the only serialization behavior in scope; there is no edited-document serializer.

# Required implementation
1. Add a focused `src/document` source-save API and module README. It accepts bounded source/path slices and caller-owned tokenizer storage, runs the XML tokenizer before opening or changing the destination, and saves only the exact original byte slice after successful parsing.
2. Add a macOS atomic-file adapter behind `src/platform/platform_atomic_file.h`. It must reject invalid path slices, oversized paths, missing/non-regular destinations, and unsafe arithmetic; create an exclusive temporary file in the destination directory; preserve existing permission bits; handle partial writes and `EINTR`; fsync the completed temporary file; atomically rename it over the destination; fsync the parent directory; and clean up temporary files on every pre-commit failure.
3. Define stable result/error categories and document the rename commit point. A write, file-fsync, permission, or rename failure before commit must leave the original destination bytes and mode unchanged. Report a parent-directory fsync failure as a durability error after commit without claiming the prior file is still present.
4. Provide a narrow injectable I/O seam for deterministic write and rename failures. Test callbacks may fail once, but production defaults must call the native macOS operations. Do not add a general filesystem abstraction or unsupported-platform implementation.
5. Add deterministic tests using project-authored XML byte fixtures that include metadata, namespace declarations, comments, significant whitespace, mixed LF/CRLF/CR line endings, and quote styles. Compare saved bytes and SHA-256 exactly. Also test malformed XML, empty/oversized paths, permission preservation, partial writes, injected write/rename failures, original-target preservation, and temporary-file cleanup.
6. Keep each new source/test file below 500 lines where practical and below 800 lines hard. Record file size and relevant save latency only if measured with a documented method; do not make SVG rendering performance claims.
