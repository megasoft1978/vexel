## Decisions

- **Toolchain:** use stable Rust **1.99.0**, released **2026-10-01**, and Rust 2024 edition as the initial pin candidate, to be frozen by the coordinator’s toolchain order. Rust’s standard library and toolchain are generally dual-licensed **Apache-2.0 OR MIT**; Vexel’s own MPL-2.0 license stays unchanged. [Rust release announcements](https://blog.rust-lang.org/releases/), [Rust licensing](https://github.com/rust-lang/rust/blob/main/COPYRIGHT), [Rust editions](https://doc.rust-lang.org/releases.html).
- **Dependencies:** start with **no new parser, SVG, geometry, or raster crate**. Keep parsing and rendering owned. Rust stable’s `std::arch` exposes target intrinsics; portable `core::simd` remains nightly-only, so keep a scalar implementation as the reference and consider isolated AArch64 NEON only after profiling and parity review. Scoped standard-library threads have been stable since 1.63. [Rust AArch64 intrinsics](https://doc.rust-lang.org/stable/core/arch/aarch64/index.html), [portable SIMD status](https://doc.rust-lang.org/nightly/core/simd/index.html), [`thread::scope`](https://doc.rust-lang.org/stable/src/std/thread/scoped.rs.html).
- **Optional geometry crate:** `kurbo` **0.13.1**, **Apache-2.0 OR MIT**, provides curve and path geometry, but adds dependency/provenance review and does not replace the owned SVG path parser or rasterizer. I recommend deferring it; revisit only if measured implementation cost justifies an ADR and pinned provenance record. [Kurbo manifest](https://github.com/linebender/kurbo/blob/main/Cargo.toml), [license and scope](https://github.com/linebender/kurbo).
- **Semantics:** treat [XML 1.0 Fifth Edition](https://www.w3.org/TR/REC-xml/) and the current [SVG 2 specification](https://www.w3.org/TR/SVG/latest/pservers.html) as semantic references, not source to copy. Local references stay local; external SVG/resource fetching remains unsupported. Preserve unknown XML and Inkscape metadata in original source bytes.

## Modules, ownership, and interfaces

There is no `src/scene` today. `src/svg/shape` currently owns the decoded geometry/style document consumed by `src/raster`; extract a separate scene module only when a stable Rust interface warrants it.

- **XML/index:** port `src/svg/xml/{xml_chars,xml_doctype,xml_reader,xml_tokenizer,xml_stream}`, then `src/svg/index`. Proposed contract: parse an immutable borrowed byte slice with explicit non-raisable limits; emit tokens and diagnostics with half-open source byte spans. Keep resumable scan/validation and cancellation separate from one-shot tokenization. Do not normalize or mutate source.
- **Geometry/style/reference:** port `src/svg/css`, `src/svg/reference`, `src/svg/shape/{shape_path,shape_geometry,transform,viewport,traverse*,shape_style,decode}` and `src/svg/paint`, `src/svg/clip`. CSS/color, path math, and reference-index work can be disjoint after shared types are fixed; shape traversal/decode should have one owner. Paths and unknown attributes retain source spans. Use an immutable `Arc<[u8]>` at document lifetime boundaries if ownership must cross tasks; indexes store offsets, not self-references.
- **Scene/effects/media:** port the remaining `src/svg/shape` files, including filters, masks, patterns, markers, text/image, and `src/svg/animation`. Preserve the existing injected media-provider seam; text shaping and PNG/JPEG decoding remain behind macOS providers.
- **Raster:** port `src/raster/tile*`, scalar fill/sample/stroke/group, bounds/scanline, preflight/filter and animation rendering. Proposed boundary: immutable decoded document plus tile request and limits yields an owned RGBA tile or stable diagnostic. Keep scalar operation order and renderer limits intact. Parallel tile rendering is a later option: tile ownership and deterministic composition must be explicit.

## Risks and unknowns

The XML spec is broad; today’s parser intentionally excludes DTD/entity expansion and namespace resolution. Unknown markup preservation is a source-editing invariant, not automatic from rendering tests. CSS cascade, `<use>` instance identity, effect dependencies, animation overlays, text shaping, and float rounding are high-parity risks. Rust ownership helps express lifetimes but does not bound `Vec` growth or geometry work by itself; retain checked arithmetic and explicit byte, depth, node, edge, reference, pixel, scratch, and work caps. SIMD and concurrency can change rounding or paint order; only add them behind scalar comparisons. Existing synthetic fixtures do not establish broad Inkscape compatibility; fixture provenance needs review before adding external samples. No speed or binary-size improvement is guaranteed; measure per stage and on supported Apple Silicon hardware before setting targets.
