## Decisions and current technical evidence

- **Facts, checked 2026-10-14:** Rust **1.98.1**, released 2026-09-03, is the current stable release; the Rust compiler and standard library are MIT OR Apache-2.0. `aarch64-apple-darwin` is Tier 1 and supports macOS 11+, so macOS 13 can be set as Vexel’s higher deployment target. Cargo workspaces support shared package coordination. [Rust release notes](https://doc.rust-lang.org/stable/releases.html), [Rust licensing](https://github.com/rust-lang/rust/blob/main/COPYRIGHT), [Rust Apple target](https://doc.rust-lang.org/rustc/platform-support/apple-darwin.html), [Cargo workspaces](https://doc.rust-lang.org/cargo/reference/workspaces.html). Rust project licensing is permissive, but the project remains MPL-2.0 per owner direction.
- **Decision recommendation (inference):** use a macOS-only Cargo workspace, stable toolchain pinned after the coordinator verifies installed toolchain and build needs; checked-in `Cargo.lock`; no cross-platform targets. Keep unsafe confined to documented platform FFI modules, with safe Rust domain interfaces and explicit ownership of buffers, snapshots, cancellation, and UI-thread callbacks.
- Candidate initial dependencies, **not yet approved or pinned**: `serde 1.0.229` (MIT OR Apache-2.0) and `serde_json 1.0.154` (same licenses), and `cssparser 0.38.0` (MPL-2.0, Rust 1.85). `objc2` has MIT for core crates and MIT/Apache/Zlib for others; its upstream says Apple SDK-derived bindings may raise distribution-license questions. Review selected framework crates individually or retain a small documented raw FFI surface. [Serde manifest](https://github.com/serde-rs/serde/blob/master/serde/Cargo.toml), [serde_json manifest](https://github.com/serde-rs/json/blob/master/Cargo.toml), [cssparser manifest](https://github.com/servo/rust-cssparser/blob/main/Cargo.toml), [objc2 license note](https://github.com/madsmtm/objc2/blob/main/LICENSE.md).
- **Inference:** preserve the owned SVG/XML tokenizer, DOM/source spans, resolver, geometry, renderer and rasterizer. A CSS syntax tokenizer dependency may be separable, but parsing, unknown-source preservation and supported SVG behavior stay Vexel-owned. No application-side external SVG fetching.

Paths below are from the inventory; split large families into bounded crates/modules to retain the project’s under-800-line source rule. Each order should assign one writer per scope; coordinator alone owns manifests, lockfile, shared interfaces and ledgers. Build a runnable slice at each merge.

2. **Wave A (independent after interface freeze):** base/jobs/spatial (`src/base`, `src/jobs`, `src/spatial`); XML/index (`src/svg/xml`, `src/svg/index`); document/source-save (`src/document`); MCP JSON/protocol/socket core (`src/mcp` protocol subset); test/benchmark harness inventory and golden-input contract (`tests`, `bench`, `scripts` interfaces). 3. **Wave B:** SVG CSS/paint/reference/clip/shape/geometry/animation and owned raster (`src/geom`, `src/svg/{css,paint,reference,clip,shape,animation}`, `src/raster`), dependent on XML; project bundle/timeline/recovery (`src/project`, platform storage seam), dependent on document; UI core/widgets/state (`src/ui`), dependent on renderer interfaces; platform services (`src/platform/macos`), dependent on frozen FFI boundary. About **8–20 days per lane**; renderer is highest uncertainty.
4. **Wave C:** editor/application integration (`src/app`, `app/`); MCP broker/export/jobs plus app hook/CLI (`src/mcp`, app MCP files), dependent on project/render/platform APIs; Rust developer, packaging, benchmark, fuzz, report and test tooling (`dev`, `scripts`, `bench`, `reports`, `packaging`, Python tests). About **8–20 days per lane**.
5. **Sequential finish:** parity gaps and product finish line, then broad UI/E2E, accessibility, security, performance measurement and demonstration recording. Estimate **15–35+ days**, highly uncertain.
