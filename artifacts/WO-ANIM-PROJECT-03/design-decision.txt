WO-ANIM-PROJECT-03 design investigation
Date: 2026-10-13

The frozen revision 1 integration contract required semantic timeline validation against all SVG scene IDs while supporting container scenes up to 256 MiB and forbidding a second unbounded token tree. Current `svg_xml_tokenize_large` requires a caller-owned complete token vector. Current `svg_xml_token_stream_start/step` is incremental in parse budget but retains every token up to `max_storage_bytes`; it does not offer token-discarding callbacks. XML attribute entity decoding is private in `src/svg/shape/text.c` and has no reusable public API.

Reusing `document_edit_create` was rejected for this integration seam: it builds a full mutable document model and editor indexes/history, which would add unnecessary retained state and does not provide a suitable minimal project-layer contract. Reusing shape decode also does not retain a general SVG ID inventory.

Decision: stop before application code changes. Restore WO-ANIM-PROJECT-03 to its original frozen revision 1 and supersede it before implementation. Add WO-XML-STREAM-01 as the prerequisite for a discard-mode tokenizer visitor plus shared bounded attribute entity decoder. After it is accepted, draft WO-ANIM-PROJECT-04 for bounded scene-ID collection, native timeline load validation, opaque future-version preservation, and exact save round-trip.

No UI/E2E tests were run. Focused implementation checks from WO-ANIM-PROJECT-02 remain recorded there; that work order remains pending a valid final independent review.
