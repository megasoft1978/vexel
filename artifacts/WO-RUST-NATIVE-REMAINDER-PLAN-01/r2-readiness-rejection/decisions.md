# Decisions and unresolved proof gates

1. **Keep the Apple crate independent of scene/UI/base.** `vexel-platform-apple/Cargo.toml` currently depends on none of those crates. Do not add a dependency or cycle. Native Apple modules expose platform-owned safe DTOs: `NativeTextLayout { glyphs: Vec<NativeGlyph>, commands: Vec<NativePathCommand>, metrics }`, `NativeImage { rgba: Vec<u8>, byte_count, row_stride, width, height }`, and `NativeMediaError`; calls borrow `&[u8]`/`NativeTextRequest`, accept the existing platform `WorkBudget` callback only after coordinator contract review, and return owned values. Root composition crate implements `vexel_scene::MediaProvider` by translating DTOs and `WorkControl` cancellation/charges, then validates the scene return types. Existing accepted `MediaProvider` requires text and image and no fake/default. The adapter crate depends on both scene and platform only once its separately reviewed manifest/workspace gate is accepted. No platform crate imports scene/UI.

2. **`TextDraw` needs an installed real root adapter.** `vexel-ui::TextDraw<'a>` is an optional mutable callback stored by `WidgetCanvas`; absent callback can leave content undrawn. Root composition owns the adapter closure that calls a platform-owned CoreText coverage raster method, passes it to every production canvas and propagates `false` as rendering failure. Apple crate does not import `vexel-ui`. No shared UI interface change unless coordinator issues a separately reviewed contract order.

3. **Selected binding closure exists; do not activate more features.** `vexel-platform-apple/Cargo.toml` presently selects AppKit NSVisualEffectView, NSImage, NSBezierPath, NSGraphicsContext, AppKit menus/panels/AX/text input, Foundation NSProcessInfo/NSUserDefaults/notifications/runloop/exceptions, CoreText CTFont/CTLine/CTRun, CoreGraphics contexts/path/images, ImageIO source/destination, Metal resources/commands/pipeline and QuartzCore CAMetalLayer. Exact pins and disabled defaults are in that manifest and `docs/dependencies/objc2-macos.lock.json`; ADR0026 locks the 16-package selected graph and ADR0027 adds NSVisualEffectView/cursor classes/NSProcessInfo. Audit artifact retains cached crate declarations and Apple SDK 27 extracts. New features are **not proposed** absent a specific declaration gap; do not use unselected CGImageSourceDestination or class APIs without proving current cached declaration and selected feature.

4. **SDK 27 does not establish macOS 13 runtime availability.** Use retained `artifacts/WO-RUST-NATIVE-BINDINGS-AUDIT-01/primary/availability-*.txt` and `sdk-*.txt` per symbol/class/function. Guard any API newer than 13 and keep older path valid. NSVisualEffectView is accepted only behind existing macOS 26 material gate (ADR0027); never replace with NSGlassEffectView. Binding compile/source evidence does not prove runtime/UI parity. Full macOS 13 GUI coverage remains future work.

5. **ABI and native ownership use accepted ADR0026 contract.** MainThread capability, private native handles, `!Send + !Sync` AppKit owner, catch-all `guard_native_call` at each public native operation and inbound Objective-C/C/block callback, owned bounded error latch, no Rust panic/Objective-C exception crossing those boundaries, no model borrow across reentrant native call. The accepted helper catches objc2 translated exceptions but raw C/CF calls, retain/release/destructors and abort cannot all be fenced; do not claim universal recovery. Invalidate generations, cancel work, unregister observers/delegates/AX targets, drain GPU work and release owners in ordered teardown. Late callbacks must be no-ops after generation invalidation.

6. **Canonical preservation inputs resolved.** Use `artifacts/WO-RUST-PLAN-01/source-baseline.json` (603-file baseline and recorded HEAD/index hash) and `artifacts/WO-RUST-RENDER-CONTRACT-PLAN-01/assertion-assignments.json` (case/assertion hashes and sole owners). R2 JSON embeds matching native suite records and assertion/case ownership. `artifacts/WO-RUST-NATIVE-WINDOW-01/coordinator-result.md` records prior 603 legacy/157 oracle preservation; coordinator still performs the mandated independent audit against these exact inputs.

7. **Testing/runtime are distinct.** The accepted window result records focused source tests and locked offline check, but explicitly does not accept live GUI/macOS 13/timer/IME/display/cursor/runtime. Existing native code and older tests are assignment evidence only. Every full lane needs its own Rust parity tests and later real GUI acceptance; no test/build/runtime was run or inferred for this order.

8. **Module registration is a coordinator gate before worker checks.** Before any implementation order starts, coordinator creates and reviews the platform-owned Rust DTO contract and module declarations in `vexel-platform-apple/src/lib.rs`, plus private `native_*` module roots and compile-visible minimal declarations. A worker must never claim a body/test is compiled while unregistered. Root app crate modules and `vexel-scene`/`vexel-ui` adapters are separately declared only by coordinator after crate boundary review, workspace member/dependency graph update and locked dependency provenance gate. Workers own bodies/tests in disjoint registered module paths; coordinator alone changes `lib.rs`, manifests, lockfiles, shared traits, workspace membership and ledgers. After each worker handoff coordinator runs exact crate target check/tests, full workspace focused checks, and integration gate; these are future evidence, not performed here.

9. **New interface types require review before coding.** The platform DTO family above, its error mapping, checked buffer ownership, and cancellation/work accounting form an interface-contract order. It must be accepted before media workers begin. This is first-party Rust contract work, no dependency change. If it cannot express existing bounded cancellation without importing scene/base, coordinator must either approve a narrow first-party dependency setup with an acyclic graph and tests or keep cancellation at root adapter boundary; do not silently use unbounded native calls.

10. **Symbol-level framework proof is a per-worker API gate.** Current selected feature names are in `rust/crates/vexel-platform-apple/Cargo.toml`; pinned declarations are under `artifacts/WO-RUST-NATIVE-BINDINGS-AUDIT-01/coordinator-primary/objc2-*-*/src`, SDK availability extracts under `.../primary/availability-*.txt` and `sdk-*.txt`. Proven examples: `CAMetalLayer` macOS 10.11 (`availability-QuartzCore-CAMetalLayer.h.txt`), MTLResidencySet macOS 15 only (forbidden on 13), and NSApplication `activate` macOS 14 (guard or avoid). Each worker order must record called selector/function to declaration file+line, selected feature and SDK minimum. Do not assume NSFont, MTLResidencySet, macOS-26 APIs or methods from a feature name alone. Missing generated bindings require a proposed metadata/feature order citing exact cached and SDK declarations, followed by ADR review; no adoption here.

11. **Existing native-window seams.** `NativeApp::start(MainThread)`, `create_window(WindowConfig)`, `poll_events(WindowId,max)`, `destroy_window(WindowId)`, `shutdown()` are in `native_window/app.rs`; `Window` operations in `window.rs`; `WindowId {slot,generation}` and event/config DTOs in `types.rs`; private `NativeView` and delegate/input methods in `callbacks.rs`; weak generation `RouteState` callback/emit/invalidate in `route.rs`; ordered cleanup in `teardown.rs`. Remaining work attaches per-window presenter/adapters through private window-owned registered state, never raw `WindowId` alone or a global pointer. Inventory records the helper/method sources. Source acceptance does not imply runtime acceptance.
