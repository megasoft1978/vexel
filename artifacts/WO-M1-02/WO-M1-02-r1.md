# Goal
Present a bounded deterministic CPU RGBA tile in the M1-01 macOS window through Metal and prove exact tile readback.

# Context pointers
- Read: `AGENTS.md`, `OWNER-DIRECTIVES.md`, `STATE.md`, `docs/CODING_STANDARD.md`, `docs/research-r3/plan/02-architecture.md`, `docs/research-r4/05-revised-roadmap.md`, `src/platform/platform_window.h`, `src/platform/macos/README.md`, `app/test_driver/README.md`.
- Relevant ADRs: macOS-only and C17 decisions in `docs/adr/`.
- Frozen tests/oracles: do not change `tests/oracle/**`, `tests/golden/**`, `bench/corpus/**`, or prior benchmark baselines.
- External docs: Apple Metal and CAMetalLayer documentation only; do not use external SVG-editor code.

# Existing contracts and invariants
- Public application interfaces remain C17; Objective-C/Metal details stay under `src/platform/macos/`.
- AppKit and Metal lifecycle calls run on the main thread. The caller owns submitted CPU bytes until the synchronous upload call returns; no retained caller pointer.
- Tile dimensions are positive, bounded to 4096 per axis; checked multiplication is required before allocating or uploading `width * height * 4` RGBA bytes.
- Preserve M1-01 window lifecycle/event behavior. Apple Silicon macOS 13+ only. No other OS stubs, third-party dependencies, external SVG fetches, or GPL editor source.

# Required implementation
1. Add a focused scalar tile module that produces a deterministic RGBA test pattern with explicit buffer ownership, checked size arithmetic, and a small documented C API.
2. Add a macOS Metal presentation adapter behind a C interface. Upload the CPU tile, render it into the current drawable, and keep Metal objects private to the macOS implementation.
3. Expose a deterministic test path that reads back the uploaded Metal texture and compares every RGBA byte with the scalar CPU tile; report the first mismatch with bounded diagnostics.
4. Extend native UI-driver smoke to resize the window and present/read back at least one frame, then verify reset/resize leaves the next frame valid. Do not use sleeps for synchronization; wait on explicit command completion with a finite timeout.
5. Document the tile contract, transfer/presentation flow, bounds, ownership, framework usage, and native smoke invocation.
